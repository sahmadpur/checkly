# Checkly i18n design (en / az / ru)

Date: 2026-09-15

## Goal

Checkly works fully in English, Azerbaijani and Russian: UI, validation and server errors, in-app / push / email notifications, dates and enum labels.

## Decisions

- **Locale source: cookie + user setting, no URL prefix.** `i18n/request.ts` resolves cookie `locale`, then the first supported language in `Accept-Language`, then `en`. Login copies `User.locale` into the cookie; `setLocaleAction` writes the cookie and, when signed in, `User.locale`. Signup and invite acceptance store the cookie locale on the new user. `proxy.ts` is untouched.
- **Library: next-intl 4 without routing.** `NextIntlClientProvider` in the root layout; `useTranslations` in client components, `getTranslations` in server components and actions. Code that runs outside a request (cron tick, emails, tests) uses the pure `translatorFor(locale)` from `lib/i18n.ts`.
- **Messages** live in `messages/<locale>/<namespace>.json`, one file per namespace so parallel work does not conflict. `MESSAGES: Record<Locale, typeof en>` plus `global.d.ts` give compile-time key checking; `tests/unit/messages.test.ts` checks key parity and that every ICU message renders.
- **Server errors are keys.** `AppError(code, key, params?)`; `run()` in `lib/actions.ts` translates `errors.<key>` in the request locale. Zod issues are re-mapped through zod's own `az`/`ru` locale maps; `en` keeps zod's default text.
- **Notifications store params, not text.** `Notification.params` (JSON) holds template, property, dueAt, tz, comment, worker; `renderCopy(type, params, locale)` renders at read time for the viewer and at send time for the recipient (`User.locale`). `title`/`body` are nullable and only used as a fallback for rows created before this change.
- **Fonts** switch to Inter (body) and Manrope (display), both with Cyrillic and Latin-ext subsets. CSS variables are unchanged.
- **English strings stay byte-identical** so Playwright's text assertions keep working; `playwright.config.ts` pins `locale: "en"`.
- **Dates** go through `formatDateTime` / `formatInTz` / `weekdayName` in `lib/format.ts` with a locale argument. The `en-US` formatter in `lib/schedule.ts` is timezone math, not display, and stays.
- **Translations** for az and ru are drafted by Claude and flagged for native review.

## Out of scope

`manifest.ts` (brand name), the decorative `auth-visual.tsx` mock copy, a custom `not-found.tsx`, org-level default locale, q-weight parsing of `Accept-Language`.
