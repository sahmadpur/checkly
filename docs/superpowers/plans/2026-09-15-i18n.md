# Checkly i18n: en / az / ru

## Context

Checkly is English-only: 76 tsx files with hardcoded copy, ~75 server error strings returned raw by `lib/actions.ts`, notification title/body persisted in the DB as rendered English, `formatInTz` pinned to `en-US`, fonts without Cyrillic. The app must work fully in Azerbaijani, Russian and English: UI, validation errors, in-app/push/email notifications, dates.

Decisions taken with the user:
- Locale from cookie + user setting, **no URL prefix** (`proxy.ts` untouched).
- Notifications store `params`; rendered per viewer/recipient at read/send time.
- Swap fonts to a Cyrillic-capable pair (Inter body, Manrope display).
- Claude drafts az and ru translations (flag for native review).

Verified facts: `next-intl@4.14.5` re-exports `createTranslator` (pure, no request context) and works without routing (`NextIntlClientProvider` needs no props); `getLocale`/`getTranslations` work in server components, actions and `generateMetadata` but throw outside a request (vitest). zod 4.6 ships `z.locales.az` and `z.locales.ru`; no schema sets custom messages, so per-issue re-mapping is safe. Inter and Manrope both carry `cyrillic, cyrillic-ext, latin, latin-ext` in `next/font/google`.

## Design

**Locale resolution** (`i18n/request.ts`, `getRequestConfig`): cookie `locale` if valid → first of az/ru/en in `Accept-Language` → `en`. Login sets the cookie from `User.locale`; `setLocaleAction` sets the cookie and, when signed in, `User.locale`. Signup / invite-accept copy the cookie locale into the new user row. Cron tick, emails and tests use the pure `translatorFor(locale)` from `lib/i18n.ts`.

**Messages** `messages/{en,az,ru}.json`, namespaces: `common, nav, auth, properties, checklists, templates, schedules, team, settings, notifications, errors, enums, email`. ICU plurals (ru: one/few/many/other). `MESSAGES: Record<Locale, typeof en>` so TS enforces key parity.

**Errors**: `AppError(code, key, params?)`, `message = key`. `run()` translates `errors.<key>` in the request locale; ZodError issues re-mapped through `z.locales[locale]().localeError` (en keeps `issue.message` byte-identical).

**Notifications**: `Notification.params Json?`, `title/body` nullable. `renderCopy(type, params, locale)` replaces `buildCopy`; old rows fall back to stored title/body.

**English strings stay byte-identical** so the 61 Playwright text assertions need no change (`playwright.config.ts` gets `use.locale: "en"`).
